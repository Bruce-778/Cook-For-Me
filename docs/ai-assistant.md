# 问小厨：DeepSeek 饮食助手

## 能做什么

“问小厨”把用户的时间、人数、现有食材、口味、忌口和一般性饮食目标转换为本站真实菜谱推荐。模型只能返回菜谱目录中存在的 `slug`，服务端会再次过滤不存在的菜谱和用户明确声明的过敏原冲突。

## 明确边界

- 不进行疾病诊断、治疗或药物建议，不声称食物能够治病。
- 生病、孕期、哺乳、慢性病、术后等场景只给一般性饮食支持，并提醒按医生或注册营养师意见执行。
- 严重胸痛、呼吸困难、意识不清等紧急描述不调用模型，直接进入本地急救分流。
- 减脂回答禁止极端节食、断食、催吐、减肥药和固定超低热量建议。
- 过敏原过滤在模型之外由服务端再次执行；仍提醒用户核对调料标签与交叉接触。
- 用户明确说不吃某类肉、吃素/纯素或遵循清真饮食时，服务端也会在模型返回后再次过滤，不能只依赖提示词约束。
- 食材过敏原统一来自 `food-metadata.ts`；奶、芝麻、大豆、麸质、鱼、甲壳类及软体贝类等会参与过滤，蚝油/酱油等复合调料也需纳入。规则是保守文本匹配，不能识别用户未说明的品牌差异或交叉接触。

## 数据与密钥

- `DEEPSEEK_API_KEY` 只放在本地 `.env.local` 或部署平台的服务端环境变量中，绝不能使用 `NEXT_PUBLIC_` 前缀。
- `/ai-status` 是仅供项目维护者使用的脱敏诊断页：显示模型、接口地址、变量是否存在、密钥长度/不可逆指纹和一次性连通性探测，不显示完整密钥。生产环境必须设置服务端 `AI_DIAGNOSTICS_TOKEN`，诊断 API 未授权时返回 404。
- API 只发送当前问题、最多 6 条短历史和精简的站内菜谱目录，不发送收藏、浏览记录等本地数据。
- 当前按请求来源做每分钟 8 次的基础频率限制，单条问题不超过 800 字。

## 运行与校验

```bash
pnpm validate:ai
pnpm typecheck
pnpm lint
```

没有配置 DeepSeek 密钥或上游暂时不可用时，接口会返回基于站内标签的保守兜底推荐，页面不会暴露密钥或上游错误详情。

## 维护原则

更新模型前先核对 DeepSeek 官方模型列表和 JSON Output 文档；新增疾病或过敏场景时，同时更新提示词、本地风险规则和 `validate:ai` 测试。通用健康表达遵循“充足、平衡、适量、多样”的原则，疾病食养内容应以国家卫生健康委等权威指南为依据，不把通用建议写成个人医疗处方。
