# Cook for Me 产品与内容安全审计（2026-07-16）

> 历史快照：本报告记录 2026-07-16 的状态与当时的处理。现行菜谱数量、审核状态和页面行为以项目根 `README.md` 与 `docs/content-maintenance.md` 为准。

## 审计范围

按真实用户路径检查：首页 → 发现菜谱 → 菜谱详情 → 烹饪模式 → 食物盲盒。重点判断“用户是否能凭页面稳定、放心地做出一道菜”，而不是只检查页面是否能打开。

## 关键结论

### P0：必须在公开上线前解决

1. **75 道菜仍由烹饪方式模板自动生成步骤。** 同属“快炒”或“红烧”不代表糖、醋、酒、淀粉、油量、腌制和下料顺序相同。现已把 79 道未完成逐道来源核验与复做验证的菜标为“复核中”，停用烹饪模式、结构化搜索数据和盲盒推荐。
2. **图片与菜名错配且外链不稳定。** 原数据让 80 道菜复用 7 张大类图片，浏览时出现红烧肉、鸡翅等共用同一张鸡肉配菜图，详情页还会出现外链空白。现已移除所有未核验图，只保留番茄炒蛋本地且匹配的成品图；今后必须一菜一图、人工核验后才能启用。
3. **分步用量不能重复整道菜总量。** 原步骤会在“炒蛋”“回锅”“装盘”重复显示 3 个鸡蛋，用户无法判断是否需要再次加入。现为已复核菜建立 `ingredientAmounts`，并校验每项分步取用合计等于总清单。
4. **来源不能用搜索页代替。** 已复核菜至少需要两个直接来源；B 站搜索只作视频兜底，不作为菜谱正确性的证据。

### P1：内容扩充时同步完成

1. 每道菜至少完成一次按页面实烧和一次独立复做，记录锅具、灶具、实际耗时和成品偏差。
2. 离散食材（鸡蛋、整鱼、整蟹、鸡翅）需区分“购买数量”和“实际取用量”，人数换算后不能出现 1.5 个鸡蛋或 0.7 条鱼。
3. 过敏原要覆盖复合调料中的隐藏来源，例如蚝油、豆瓣酱、甜面酱和成品酱汁；忌口过滤以配料而不是菜名判断。
4. 加入“报告这道菜的问题”，让用户选择用量、步骤、时间、图片、视频或过敏原问题，并保存菜谱版本，便于回溯修改前后的内容。
5. B 站精选视频应保存 BV 直链、标题、UP 主、核验日期，并定期检查失效；视频与本站用量不一致时明确以本站已复核正文为准。
6. 食品安全除“熟透”外，还应覆盖剩菜冷藏、再次加热、婴幼儿现场看护、鱼刺/碎骨、四季豆彻底熟透和高温油飞溅等菜品专属风险。
7. 盲盒只能使用已复核菜谱；复核数量不足时宁可明确提示暂不能组成整桌，也不能用草稿凑数。

## 已完成的防误导改动

- 引入 `reviewed / draft` 编辑状态和 `imageVerified` 图片状态。
- 首页、排行榜和盲盒只消费已复核内容；草稿详情禁止进入烹饪模式并禁止搜索引擎收录。
- 图片只在本地文件存在并经人工视觉核验后显示。
- 已复核步骤展示火候、水温、油量、油温、计时、完成状态、专属安全提示和精确本步取用量。
- 详情页公开来源、来源类型、核验日期与内容核验范围。
- Supabase 同步只允许带复核状态的菜进入 `published`，且仍不写入任何种子点赞。

## 后续验收门槛

- 80 道菜全部通过逐道实烧、交叉来源、分步用量守恒和图片视觉核验。
- 任何已发布菜都不存在模糊用量、清单外加料、泛化步骤、重复错图或搜索页充当来源。
- 点赞、周榜、收藏、烹饪模式、盲盒、购物清单在手机和桌面完整走通。
- `pnpm lint`、`pnpm typecheck`、`pnpm validate:content`、`pnpm validate:videos`、`pnpm build` 全部通过。
