# 菜谱与 B 站视频维护流程

这套流程用于持续增加或更新菜谱。新内容默认留在审核状态，不允许为了更新速度跳过逐道核验。

## 新增或更新一道菜

1. 在 `src/lib/recipes.ts` 的 `CATALOG` 中新增或修改菜谱基础数据，保持 slug 稳定且唯一。
2. 逐项核对食材克数/毫升、火候、水温、油温、时间和完成状态；不能使用“适量”“少许”等模糊词。
   - 先做一次台面复核：按页面称量全部食材，确认没有清单外临时加料。
   - 再做一次实烧复核：记录实际锅具、灶具档位、下锅状态、耗时和成品状态；只把本步首次实际取用的数量计入 `ingredientAmounts`，后续“回锅”“装盘”不重复计算。
   - 酸甜、红烧、鱼香、宫保等复合味必须单独核对糖、醋、酱油、料酒、淀粉和油的比例，不能继承通用炒菜模板。
3. 至少保留两个来源，并把来源名称、URL、核验日期写入菜谱数据。宝宝、老人和清淡恢复类还要对照权威膳食指南。
   - 两个来源应当直接描述同一道菜；搜索结果页、聚合页和 AI 成品图不能充当做法来源。
   - 发布前由另一位审核者按页面独立复做一次；未复做的内容只能保持 `draft`，不能开放烹饪模式或进入盲盒。
4. 运行 `pnpm validate:content`，修复全部结构与覆盖量错误。
5. 录入 B 站视频时，先完整播放确认菜名、主料和关键做法相符，再填写以下四项：
   - `bilibiliVideoUrl`：`https://www.bilibili.com/video/BV...` 具体视频直链；不能填写搜索页。
   - `videoTitle`：视频原始标题。
   - `videoCreator`：UP 主名称。
   - `videoVerifiedAt`：最后人工播放核验日期，格式为 `YYYY-MM-DD`。
6. 每道菜都保留 `bilibiliSearchUrl`。精选直链缺失或失效时，详情页会自动退回“搜索同名做法”。
7. 运行 `pnpm validate:videos`；正式要求全部菜都已有直链时运行 `REQUIRE_DIRECT_BILIBILI=1 pnpm validate:videos`。
8. 先运行 `pnpm seed:supabase` 同步为 `review`，抽查详情页后再使用 `PUBLISH_REVIEWED_RECIPES=true pnpm seed:supabase` 发布。

## 成品图启用标准

1. 每道菜使用独立本地文件，路径固定为 `/images/recipes/<slug>.webp`；禁止继续按大类复用同一张图。
2. 生成提示词必须写明主料、切法、酱汁颜色、成品形态、容器和中式家常菜摄影风格，并要求 4:3、无文字、无水印、无人手、无品牌餐具。
3. 人工对照菜谱核验四项：主料是否正确、切法/形态是否正确、颜色/汁水是否合理、是否混入菜谱没有的明显配菜。
4. 只有文件存在且人工核验通过后才设置 `imageVerified: true`。未通过时页面不显示图片，避免用“差不多的图”误导用户。

## 视频复核标准

- 页面内只把具体 BV 视频页称为“已核验视频”，搜索结果页永远只作为兜底。
- 视频只是帮助用户观察状态，不覆盖本站的精确用量、火候和食品安全说明。
- 视频失效、改标题、内容被替换或做法与本站明显冲突时，立即清空精选直链并保留搜索兜底。
- 建议每 30 天复核一次已发布直链，并更新 `videoVerifiedAt`。

## 发布前固定命令

```bash
pnpm lint
pnpm typecheck
pnpm validate:content
pnpm validate:videos
pnpm build
```
